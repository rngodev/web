# Log

The **log**, or run log, is the complete record of a [simulation](/docs/concepts#simulation). It's a [SQLite](https://sqlite.org) database that holds every input, output and piece of metadata the simulation produced, plus the results of the [audit](/docs/concepts#audit).

## Location

Each [`rngo run`](/docs/cli/run) gets its own directory:

```bash
.rngo/runs/01a005e6-1e8f-72b2-abfc-2da7a7a8dbdf/
```

which contains:

- `spec.yml`, the full resolved spec used by the run
- `log.sqlite`, the log

The most recent run is symlinked at `.rngo/runs/last`, so you can inspect it with any SQLite client:

```bash
sqlite3 .rngo/runs/last/log.sqlite
```

## Tables

```sql
CREATE TABLE inputs (
    id INTEGER NOT NULL,
    effect TEXT NOT NULL,
    offset INTEGER NOT NULL,
    data TEXT NOT NULL
);

CREATE TABLE outputs (
    channel TEXT NOT NULL,
    input_id INTEGER,
    timestamp TEXT NOT NULL,
    level TEXT NOT NULL,
    data TEXT NOT NULL
);

CREATE TABLE metadata (
    type TEXT NOT NULL,
    input_id INTEGER,
    effect TEXT,
    offset INTEGER,
    attribute TEXT,
    data TEXT
);
```

- `inputs` has one row per input generated by an [effect](/docs/spec/effect)
- `outputs` has one row per output received by a [channel](/docs/spec/channel). An interactive output references the input that caused it with `input_id`; an ambient output leaves it empty
- `metadata` records additional information about the simulation, such as its start and end times

There's also a `signals` table, which the audit fills with the result of each [signal](/docs/spec/signal).

## Uses

The log is the data source for:

- [signals](/docs/spec/signal), which query these tables during the audit
- [`reference`](/docs/spec/schema/reference) schemas, which sample values from earlier inputs
